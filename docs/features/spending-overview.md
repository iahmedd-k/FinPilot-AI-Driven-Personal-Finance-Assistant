# Spending overview

## Purpose

The dashboard's Spending Overview is an interactive, client-rendered view of
transaction and budget data. It is implemented in
[`OverviewTab.jsx`](../../client/src/components/dashboard/tabs/spending/OverviewTab.jsx)
and receives dashboard state through its props.

## Inputs and calculations

- `apiTransactions` supplies transactions; `budget` supplies the current budget
  amount; `monthlyChart` and currency settings are also passed by the dashboard.
- The view chooses its reference month from the latest available transaction
  date and offers a selector covering up to six months.
- Expense and income transaction types are normalized separately. The
  selected-month spending chart accumulates expense amounts by day and compares
  the running total with the supplied budget.
- Calendar heat-map values, recurring-item dates, category totals, report
  series, and category-history values are derived in the browser from the
  transaction collection.
- Category reporting can be viewed as a line chart, bar chart, or treemap. The
  treemap can group by category or month. Selecting a category opens a
  transaction/history detail view.

These are presentation calculations, not a second authoritative ledger. The
persisted transaction and budget records remain server-side.

## Budget update path

When a category detail budget is saved, the component posts
`{ month, amount }` to `POST /api/dashboard/budget`, invalidates the dashboard
query, invokes its save callback, and displays a success/failure notification.
The endpoint requires authentication. The component currently rejects a
non-positive or non-numeric amount before making the request; API validation
and persistence behavior are defined by the server implementation.

## Plan gating

`ProGate` wraps selected analytics/report sections. Non-Pro users see the
gated presentation and an upgrade action; it does not mean every overview
section is Pro-only. The server separately guards forecast and dashboard
export endpoints with `requirePro`.

## UX and correctness notes

- Currency rendering uses the user's preferred currency formatter. The
  displayed values are based on the amounts and categories supplied by the
  dashboard API.
- Invalid dates are skipped in some derived series; date parsing and display
  should be regression-tested when changing the transaction date format.
- A selected month is constrained to the six options generated by this view.
- Keep chart labels, calendar selection, category drill-down, budget updates,
  narrow viewport behavior, and free/Pro gates covered when editing this
  component.
